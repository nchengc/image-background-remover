## 〇、先说结论

**为什么现在没流量，只有一个根本原因：可索引的内容实体只有 5 个 URL，其中 4 个是政策页。**
在 Google 眼里，这是一个「单页工具」，没有可覆盖的查询意图面，自然不会有展现。

**本次已落地的核心动作：把站点从「单页工具」改造成「1 个枢纽 + 5 个场景长尾页」的主题集群**，
站点可索引 URL 从 5 个增至 10 个，且新增页面全部覆盖真实的长尾搜索意图。

**必须提前讲清的三条现实约束：**

| 约束 | 说明 | 应对 |
|---|---|---|
| 头部词打不赢 | 「在线抠图」「remove background」被 remove.bg / Canva / Adobe / Photoroom 垄断，新站 12 个月内不可能进前 10 | 放弃头部词，全部资源投向长尾 |
| 新站沙盒期 | 域名上线仅数日，无索引历史，Google 通常需要 3–6 个月才给出稳定排名 | 前 90 天以「收录 + 内容供给」为目标，不考核排名 |
| 产品本身有硬伤 | 免费额度每月 50 张、输出被限制在约 25 万像素 | 短期靠内容诚实说明；中期这是**流量变现的天花板**，见第七节 |

## 一、现状诊断（改造前 vs 现在）

| 维度 | 改造前 | 现在 | 对流量的影响 |
|---|---|---|---|
| 可索引 URL 数 | 5（含 4 个政策页） | 10 | 决定可覆盖的查询意图数量 |
| 内容实体 | 1 个首页，纯营销文案 | 首页 + 5 个场景深度页 | 决定长尾词覆盖范围 |
| 内链结构 | 几乎为零（页脚锚点不传递权重） | 首页枢纽 → 场景页、场景页互链、页脚全站入口 | 决定新页被抓取与权重分配 |
| 结构化数据 | WebSite / Organization / WebApplication / FAQPage | 新增 **HowTo**（首页 + 各场景）、**BreadcrumbList** | 决定富媒体结果资格 |
| 关键词覆盖 | 仅「去除图片背景」1 个词 | 覆盖 25 个场景长尾词 | 决定展现机会 |
| 孤儿页 | — | 0（每个场景页至少 6 个入链） | 孤儿页几乎不可能被排序 |

## 二、竞争格局：哪些词能打，哪些不能

### 2.1 不能打（放弃）

`在线抠图`、`抠图`、`remove background`、`background remover`、`去背景`

理由：搜索结果页前 10 位被 remove.bg、Canva、Adobe Express、Photoroom、Erase.bg、Zoviz、
美图秀秀、百度 AI 抠图等占据，这些域名有数年积累与数十万级外链。新站在这类词上投入内容
等于零回报。

### 2.2 能打（本次已建页覆盖）

这些词的共同特征：**任务具体、意图明确、竞品多为综合型页面而非专门页**——
综合页在长尾意图上的相关性天然弱于专门页，这正是新站的机会窗口。

| 目标词（主词） | 落地页 | 意图 | 竞争判断 |
|---|---|---|---|
| 证件照换底色 | `/id-photo` | 事务型 | 中。对手多为工具聚合文章，专门页稀缺 |
| 图片换白底 | `/white-background` | 事务型 | 中。同上 |
| 商品图抠图 | `/product-photo` | 商业调查 | 中高。电商内容多，但多为教程非工具页 |
| Logo 转透明背景 | `/logo-transparent` | 事务型 | 中。竞争分散 |
| 签名抠图 | `/signature` | 事务型 | **低**。竞争者最少，最可能先出结果 |

### 2.3 数据口径声明（重要）

上表的「竞争判断」来自**搜索结果页的竞品构成分析**（谁在排、排的是什么类型的页面），
**不是精确的搜索量 / KD 数值**——当前环境没有接入 Ahrefs / Semrush / 关键词规划师。

**上线后请补这一步**（约 1 小时，决定后续所有优先级）：

1. Google Keyword Planner（免费）导出上述 25 个词的月均搜索量与竞争度
2. Search Console 上线 4 周后导出「查询」报告，看实际拿到展现的词
3. 用真实数据回填本表，再决定下一批 10 个场景页做什么

**在拿到真实数据前，不要相信任何搜索量数字，包括本文件里的任何估计。**

## 三、内容架构：主题集群

```
                    ┌─────────────────────────┐
                    │   首页 /  (枢纽 pillar)  │
                    │  通用去背景 + 场景入口网格 │
                    └───────────┬─────────────┘
        ┌──────────┬────────────┼────────────┬──────────┐
        ▼          ▼            ▼            ▼          ▼
   /id-photo  /white-bg   /product-photo  /logo-...  /signature
   证件照      白底图       商品图          Logo       签名
        └──────────┴────────────┴────────────┴──────────┘
                   场景页之间互链（相关场景区）
```

**内链规则（已实现）：**

- 首页 → 每个场景页各 2 条入链（使用场景区 + 页脚）
- 每个场景页 → 其余 4 个场景页 + 首页（相关场景区 + 面包屑 + 页脚）
- 页脚在**全站**输出 5 个场景链接 → 保证任何页面都能爬到全部场景页

### 3.1 Doorway Page 红线（新增场景页前必读）

Google 会惩罚「仅关键词不同、内容互相复制」的页面矩阵。本项目防红线做法已固化在代码里：

| 措施 | 实现位置 |
|---|---|
| 每页独立 H1，且包含该场景专属词 | `lib/scenarios.ts` → `h1` |
| 每页独立 H2 标题（不复用同一措辞） | `lib/scenarios.ts` → `rulesTitle` |
| 每页 2–3 段**场景专属**导语（不是模板替换） | `lib/scenarios.ts` → `intro` |
| 每页专属行业规则表格（证件照底色 / 电商主图规范 / 签名扫描要求…） | `lib/scenarios.ts` → `rules` |
| 每页专属操作步骤与 FAQ | `lib/scenarios.ts` → `steps` / `faqs` |
| 代码注释写明红线 | `lib/scenarios.ts` 顶部 |

**新增场景的准入标准：能否写出与其他页真正不同的行业规则与避坑要点。**
写不出就不要建——宁可 5 页做深，不要 20 页做薄（后者会拉低整站质量分，并影响 AdSense 审核）。

## 五、E-E-A-T（Google 质量评估）

当前站点在「经验 / 专业 / 权威 / 可信」四项上的短板是**没有可识别的责任主体**。

## 六、国际化判断（暂缓，但要记着）

站名 `BgRemover` 是英文品牌，内容却是 `lang="zh-CN"`，定位目前是错位的。

- **英文市场规模远大于中文**（`remove background` 全球月搜索量是中文的数十倍），
  但竞争也最惨烈——remove.bg 就是靠这个词起家的。
- **中文长尾竞争明显更小**，且当前内容已全部是中文，切换成本已产生。

**建议：3 个月内不启动英文版。** 先把中文长尾做透、拿到第一批排名数据后，
再决定是否用 `/en/` 子目录 + `hreflang` 扩展。同时开两个战场会分散本就有限的内容产能。

## 七、外链与权威建设

新站域名权重为零。**唯一合规且可持续的路径是被引用，不是买链接。**

| 优先级 | 动作 | 预期 | 成本 |
|---|---|---|---|
| 1 | 完善 GitHub 仓库 README（英文），标注为 remove.bg 的开源替代实现 | 开发者自然引用，且这类链接权重高 | 低 |
| 2 | 提交到工具导航站与开源项目收录站（如 AlternativeTo、Product Hunt、各类「在线工具」目录） | 早期基础外链 | 低 |
| 3 | 写一篇真实的多去背景工具横向实测长文（含失败案例截图） | 工具测评类内容最容易被转载引用 | 中 |
| 4 | 在相关问答社区（知乎、V2EX、SegmentFault）**回答问题而非发广告** | 少量高质量引荐流量 | 中 |
| 5 | 做一个可被外部引用的小资产（如「常见证件照尺寸速查表」） | 长期被引用的资源型页面 | 中 |

**红线：不买链接、不做链接交换、不做 PBN、不在评论区群发。** 这些一旦被识别，
恢复周期以年计，且会直接导致 AdSense 拒审。

**本阶段成功标准：10 个页面全部「已编入索引」。不考核排名。**

### 第 30–60 天：扩大意图覆盖

- [ ] 审查 Search Console「查询」报告，找出已有展现但排名 11–30 位的词
- [ ] 针对这批词做**现有页面的内容加厚**（比新建页面更快见效）
- [ ] 新建 3–5 个场景页（候选：印章抠图、宠物照片、人像证件、图标素材、产品包装）
- [ ] 发布 1 篇横向实测长文
- [ ] 提交到工具目录站

**本阶段成功标准：出现第一批进入前 50 位的非品牌词。**

### 第 60–90 天：转化与迭代

- [ ] 用 PageSpeed Insights 实测 Core Web Vitals，修复不达标项
- [ ] 分析场景页的**工具使用率**（只看曝光不看转化没有意义）

- [ ] 若已过审 AdSense，接入广告并观察对体验与排名的影响
- [ ] **重新评估产品硬伤**：每月 50 张 + 0.25MP 输出是否已成为增长天花板

**本阶段成功标准：至少 1 个场景词进入前 20 位，且场景页有真实使用转化。**

## 九、衡量指标

| 阶段 | 主指标 | 目标 |
|---|---|---|
| 0–30 天 | 已编入索引页面数 | 10/10 |
| 30–60 天 | 有展现的查询数 | ≥ 20 个 |
| 60–90 天 | 进入前 20 位的目标词 | ≥ 1 个 |
| 长期 | 非品牌自然流量 | 3 个月内月环比正增长 |

**统计纪律：** 展现量波动 ±30% 以内不视为趋势；排名变化需连续 7 天同向才做决策。
新站早期数据量太小，单日波动几乎全是噪声。
